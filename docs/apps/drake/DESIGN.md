# Drake Design

## Design Concept

ドレイクのデザインは、科学館の展示のように、知的で静かで美しい体験を目指す。

宇宙人来訪説を煽るのではなく、無数の星の中から生命・知性・文明・来訪可能性が少しずつ絞られていく過程を見せる。

キーワード:

- 静かな宇宙
- 思考実験
- 光が灯る
- 可能性が絞られる
- 数式ではなく体験
- 信じる/信じないの前に考える

## Tone

避ける:

- オカルト的
- 陰謀論的
- 派手すぎる SF
- 怖い演出
- 断定的な言葉

目指す:

- 知的
- 透明
- 静か
- 美しい
- 誠実
- スマホで読みやすい

## Main Visual

WebGL による星空をアプリ全体の中心ビジュアルとする。

星空は単なる背景ではなく、確率を表すインタラクティブな可視化である。

### Star Meaning

- 白: 通常の星
- 緑: 生命が存在しうる惑星
- 青: 知性体が存在しうる惑星
- 金: 通信可能な文明
- 強く光る白または赤みのある光: 来訪候補・UFO 証拠更新

星色の意味は各ステップの `i` ポップアップ、または Result の凡例で確認できるようにする。

### Basic Behavior

- イントロでは静かに瞬く星空
- Drake 画面ではスライダーとリアルタイム連動
- Visit 画面では文明の光から来訪候補がさらに絞られる
- Evidence 画面では証拠によって来訪可能性の光が強まる
- Result 画面では「あなたの銀河」として最終状態を表示し、Intro のような瞬きと赤い来訪候補・UFO証拠更新の星群の重心へ寄る低速ズームを入れる

## WebGL StarField

### Technical Direction

- Three.js
- React Three Fiber
- 星は個別の React コンポーネントにしない
- 1 つの Points と BufferGeometry で描画する
- 星数は MVP では 2000 程度
- postprocessing / bloom は MVP では使わない
- devicePixelRatio は最大 1.5 程度に制限する
- WebGL 非対応環境では静的グラデーション背景にフォールバックする

### Star Data

各星は以下のデータを持つ。

- position
- size
- seed
- lifeScore
- intelligenceScore
- civilizationScore
- survivalScore
- visitScore

星の位置は初回生成後に固定する。

スライダーを動かしても、星の位置は変えない。同じ銀河を見続けている感覚を保つためである。

### Change Rules

生命確率が上がると、緑の星が増える。

知性確率が下がると、緑の星の中から青い星が減る。

文明確率または文明寿命が上がると、青い星の中から金色の星が増える。

来訪確率が上がると、金色の星の一部が強く光る。

数値表示には実計算の確率を使う。一方で、来訪確率のように極端に小さくなりやすい値は、星空上では変化が視認できる可視化用シグナルへ変換して表示する。これは確率そのものを誇張するためではなく、思考実験の変化を見やすくするためのサンプル表示である。

### Animation

- 変化は即時だが、色と明るさは滑らかに遷移する
- 遷移時間は 0.3 から 0.8 秒程度
- 星はゆっくり瞬く
- 背景はほぼ静止
- 激しいカメラ移動は避ける
- prefers-reduced-motion の場合は瞬きと移動を弱める

## Mobile UI

### Basics

1 画面 = 1 つの問い。

星空を主役にする。Intro 以外では、画面最上部に細いステップバー、星空上部に小型 HUD、画面下部に必要最小限の入力パネルを重ねる。

### Step Indicator

Intro を除き、画面最上部に現在地を表示する。Drake Equation から Result までを 5 ステップとして扱う。

例:

```text
存在 → 科学比較 → 来訪 → 証拠 → 結果
```

または:

```text
STEP 1 / 5
```

中央左右には控えめな矢印を置き、星空エリアでは左スワイプで次へ、右スワイプで戻れるようにする。スライダー、ボタン、リンク、証拠カード、スクロール可能なパネル上ではスワイプ移動を発火させない。

### Screen Composition

#### Intro

星空を全画面背景にする。
タイトルとサブタイトルは星空に重ねて配置する。

コピー:

```text
ドレイク

宇宙人はいるのか、来ているのか。

存在、来訪、証拠。
3つに分けて考える。
```

地球ホライズンの上に上向き矢印を置き、上スワイプまたはタップで開始できるようにする。UFO LAB TOKYO の下には `Xで共有` の小さなピルボタンを置き、閉じるボタンに見える丸い `X` 単独表示は避ける。

Intro には、ドレイクの方程式とベイズ推論を 1 行でつないだ薄い数式リボンを星空上に配置する。数式は説明ではなく、アプリの思考構造を示すイメージとして扱い、タイトルや地球ホライズンより目立たせない。

```text
N = R* · fp · ne · fl · fi · fc · L    P(θ|D) = P(D|θ)P(θ) / P(D)
```

「存在、来訪、証拠。3つに分けて考える。」の下に `Drakeとは？` を置き、下から出る Glassmorphism の説明シートで、ドレイクの方程式、ベイズ推論、このアプリが思考実験であることを短く説明する。説明には、ドレイクの方程式で存在可能性と地球来訪の事前確率を考え、UFO証拠の強さでベイズ推論に基づき事後確率へ更新する流れを含める。

#### Drake Equation

天の川銀河を対象としていることを明示し、星空上部に問いと主要メトリクスを小型 HUD として重ねる。下部には 1 項目ずつスライダーを表示する。

コピー:

```text
天の川銀河に、生命が存在しうる候補はどれくらいあるでしょう？
```

`i` には「ドレイクの式は天の川銀河に存在する通信可能な地球外文明の数を見積もる思考実験として使われる」ことを表示する。`?` には各入力項目の意味を表示する。

1 つ目の入力では、上部 HUD に `惑星を持つ恒星` と `推定される惑星` を表示し、1000 億個の恒星を仮の母数として `惑星を持つ星の割合` スライダーと連動させる。`推定される惑星` は平均 `1.6個/恒星` の簡略仮定で出す。2 つ目は `生命が存在しうる惑星`、3 つ目は `知性体が存在しうる惑星` を候補数として表示する。4 つ目で `通信可能な文明` と `通信可能な文明として続く見込み` を表示し、ここで初めて推定される文明数 N を見せる。`通信可能な文明` は Step1-3 の知性体が存在しうる惑星から連続して計算する。Drake Equation の途中段階では `存在可能性` という最終指標を出さない。

#### Science Comparison

カード UI。
カードは星空を覆ってよい前面の Glassmorphism とし、画面表示時に上から順に軽く登場する。各カードには `あなたの設定: 慎重寄り / 中間 / 楽観寄り` を明示する。
カードは上部 HUD の直下から始める。カードが長くなっても `戻る / 次へ` は下部に固定し、操作できる状態を保つ。

コピー:

```text
あなたの前提は、現在の科学と比べてどこが楽観的で、どこが慎重でしょうか？
```

#### Visit Filter

縦のフィルター UI。
Drake Equation と同様に、上部小型 HUD と下部の 1 項目スライダーで構成する。
上部 HUD には、実計算の来訪可能性に加えて `来訪候補ライト` を置き、赤/白い星が来訪候補のサンプル表示であることを短く伝える。

コピー:

```text
宇宙人が存在するとしても、地球に来るにはいくつものハードルがあります。
```

#### UFO Evidence

証拠カード UI。
証拠カードは星空上に薄く重なるコンパクトな複数選択 UI とし、星空表示領域を大きく残す。
証拠カードの横スクロールとステップ移動導線は分離し、カード選択後も `結果へ` が常に押せるようにする。
証拠プリセットは控えめに設計し、目撃や映像だけではベイズ更新が大きく跳ねないようにする。
`証拠の強さ` は倍率だけでなく、`ほぼ変わらない`, `少し更新`, `強く更新`, `大きく更新` のような言葉を主表示にする。

コピー:

```text
この証拠で、考えはどれくらい変わる？
```

#### Result

最終星空とまとめ。
Result は最初に「あなたの銀河」の星空を見せる。星空は瞬き、赤い来訪候補・UFO証拠更新の星群の重心へゆっくり寄る。フォーカス対象は UFO証拠更新の星を優先し、少ない場合は来訪候補、さらに少ない場合は通信可能な文明を使う。結果パネルは `結果を見る` で展開し、`銀河に戻る` で折りたたむ。結果内にも星色の意味を表示する。
結果パネルは上部 HUD の直下から始め、3つの予測として `通信可能な文明存在の予測`, `地球来訪の予測`, `証拠確認後の来訪予測` を表示する。各カードは青、白/赤、赤のトーンで色分けし、数値とカード面を控えめに発光させる。折れ線グラフではなく、カード内に短いテキストフローを置く。
上部 HUD には `白=通常`, `緑=生命が存在しうる惑星`, `青=知性体が存在しうる惑星`, `金=通信可能な文明`, `赤/白=来訪候補・UFO証拠更新` のコンパクト凡例を置く。

コピー:

```text
あなたの銀河
```

## Copy Policy

メイン UI では専門用語を出しすぎない。

使う:

- 存在
- 来訪
- 証拠
- 前提
- 可能性
- 更新
- あなたの設定では

控えめに使う:

- ドレイクの式
- ベイズ推論
- 事前確率
- 事後確率
- 尤度比

使わない:

- 確定
- 証明済み
- 宇宙人は来ている
- 宇宙人は来ていない

## Notes

確率表示の近くには、以下のような注釈を入れる。

```text
この結果は、あなたの前提に基づく思考実験です。
科学的な最終結論ではありません。
```

表示される確率は、ユーザーの前提と証拠評価を可視化するためのサンプル値である。天の川銀河の実際の文明数、来訪の有無、個別 UFO 事例の結論を断定するものとして扱わない。

```text
星空は確率を理解するためのサンプル表示です。
実際の銀河の星数をそのまま表しているわけではありません。
```

## SEO Design

検索用 metadata と FAQPage JSON-LD を使う。アプリ体験の下に、画面表示される SEO 説明セクションは置かない。

- 見出しには `ドレイクの方程式`, `宇宙人の存在確率`, `UFO証拠` を自然に含める
- metadata では `ベイズ推論`, `SETI`, `フェルミのパラドックス`, `グレートフィルター`, `バイオシグネチャー`, `テクノシグネチャー` を関連語として扱う
- FAQ JSON-LD でも断定表現は避け、思考実験であることを明記する
