# Jenny - UFO REPORT ANALYZER Design

## Design Intent

JennyのUIは、Jevが6件の主判定を含む20件の型付き質問を一度に評価し、その結果が5つの表示ブロックへまとまる速さを体験として見せる。

デザイン人格は「高速・精密・冷静」。研究機器のような明瞭さを持たせるが、SF端末、ゲーム画面、陰謀論的な演出には寄せない。表示する数値は実際のJev出力だけとし、処理中の雰囲気づくりを目的とした架空の数値は使用しない。

ユーザーが通常の明るい環境で長い報告文を読みながら使用することを前提に、入力面は明るく保つ。計算状態と結果だけを暗い分析面へ切り替えることで、作業の開始と完了を明確にする。

## Design Principles

- **Parallel, not sequential**：20件が同時に評価されることを、同時描画と同時更新で示す。
- **Measured speed**：速さを装飾語ではなく、実際の項目数と経過時間で示す。
- **Real values only**：数値が届くまでは数値を出さず、到着後に実値だけを描画する。
- **Five results first**：完了後の基本情報はPROJECT.mdで定義した5表示ブロックに戻し、20件の個別判定を常設しない。
- **Calm verification**：未知への関心を残しつつ、真偽や異星人起源を断定する色、文言、演出を避ける。

## Page Structure

対象ルートは `/jenny` の1画面とする。ページは次の順序で構成する。

1. コンパクトなヘッダー：UFO Lab Tokyoへの帰属、`Jenny`、`UFO REPORT ANALYZER`を表示する。
2. 短い導入文：文章をJevで20項目評価し、5指標へ整理することを1文で伝える。
3. ワークスペース：入力面とJev Analysis Surfaceを配置する。
4. 注意文：AIによる参考評価であり、真偽や異星人起源を断定しないことを示す。

独立した説明カードや機能紹介カードは並べない。中心となるワークスペース自体で製品の役割を理解できる構成にする。

## Workspace Layout

### Desktop

- ワークスペースの最大幅は `1180px` とする。
- `min-width: 900px` では、入力面44%、分析面56%の2カラムにする。
- カラム間は `24px`。入力と分析は別々のカード群ではなく、ひとつの作業領域を構成する2面として扱う。
- 初期表示では両面の高さを揃え、目安を `min-height: 560px` とする。
- 分析完了後は入力面を本文プレビューへ縮め、分析面をワークスペースの主領域として広げる。入力本文と結果を常時左右に残さない。

### Tablet and Mobile

- `max-width: 899px` では入力面、分析面の順に1カラムへ切り替える。
- 本文入力欄はモバイルで最低 `240px` の高さを確保する。
- 分析開始時に分析面へスクロールし、プログラム上のフォーカスを分析ステータスへ移す。
- 完了後は入力欄を2〜3行の本文プレビューへ折りたたむ。「入力を編集」で元の入力欄へ戻せるようにする。
- 20件の型付き判定は4列固定にせず、`768px`未満では2列、`360px`未満では1列にする。
- 主要5指標はすべて1列で表示し、ラベル、値、水平バーの順序を維持する。

## Input Surface

入力面は既存UFO Labの白いサーフェスとセージ系の操作色を継承する。

- 見出し：`目撃・調査報告を貼り付ける`
- 入力：複数行テキストエリア。本文向けの読みやすい行間と、最大 `75ch` の行長を使う。
- 補助表示：現在の文字数、アプリ側では本文を保存しないこと、AI Gateway経由でJevへ送信すること、個人情報を入力しない注意を短く案内する。
- 主ボタン：`Jevで20項目を分析`
- ボタンは入力が空、短すぎる、または分析中の場合に無効化する。
- 分析中はボタンの文言を `20項目を分析中` に変更し、二重送信を防ぐ。

分析完了後の折りたたみ状態では、本文先頭の短いプレビュー、文字数、`入力を編集`、`別の報告を分析`を表示する。

## Jev Analysis Surface

暗い分析面は装飾的な端末画面ではなく、評価状態を表示する計測面として設計する。角丸は最大 `16px`、線か短い影のどちらか一方だけを使用し、ガラス表現や強いグローは使わない。

上部には常に次を表示する。

- 状態名：`Jev Analysis`
- 現在状態：`分析待機中`、`20項目を分析中`、`分析完了`、`分析できませんでした`
- 完了時の実績：`20項目を286msで評価`の形式。項目数と経過時間は実データを使う。

分析面は待機、分析、完了、失敗の4状態を持つ。

### Waiting

- 「報告品質」「遭遇特徴」「代替説明」「証拠」「フェイク兆候」の5グループ名を静かに表示する。
- 数値、割合、仮のバーは表示しない。
- 空状態の説明は `文章を入力すると、20項目を同時に評価します。` とする。

### Analyzing

- 6件の主判定を含む20件の型付き判定を、デスクトップで4列×5行のマトリクスとして表示する。
- 応答待ち中は各セルに項目名と活動状態だけを表示し、仮のスコアやランダムな増減を表示しない。
- Jev応答後、各セルへ実際の値を同時に反映する。
- 同時性を優先し、項目ごとの長い順次表示やカウントアップ演出は行わない。

### Complete

- 20件のマトリクスを主役から退かせ、6件の主判定を5つの表示ブロックへ切り替える。
- マトリクスの個別値は完了画面へ常設せず、主要指標を開いた時だけ関連する下位判定を表示する。上部には項目数と実測時間を残す。
- `SP分類`を最上段に置き、SとPの2本を同じブロック内で最も強く表示する。
- 続けて、近接遭遇分類、TRUE UFO度、証拠強度、フェイク兆候を表示する。
- すべてを「ラベル、数値、水平バー」の共通構造にする。円グラフ、ゲージ、レーダーチャートは使用しない。
- CEはコード、分類名、選択肢別確率を同一行に置き、その確率を水平バーへ反映する。
- TRUE UFO度の直下に `異星人起源の確率ではありません` を短く表示する。
- フェイク兆候には断定を避けるため、警告アイコンや赤色を使わない。

#### Result Details

- S、P、近接遭遇分類、TRUE UFO度、証拠強度、フェイク兆候の各評価レーンを開閉ボタンにする。
- 一度に開ける詳細は1項目だけとし、同じ項目を再度押すと閉じる。
- Sと近接遭遇分類は接近度、物理・環境作用、存在者・搭乗者を表示する。
- Pは記述の具体性、時空間的一貫性、情報源の追跡性を表示する。
- TRUE UFO度は天体説明、人工飛翔物説明、気象・光学説明を表示する。
- 証拠強度は独立した複数目撃、記録・センサー証拠、物理・同時代資料を表示する。
- フェイク兆候は内部・時系列矛盾、創作・加工兆候を表示する。
- 詳細値も数値と細い水平バーで表示し、元のJev出力以外の値を生成しない。
- 開閉は200msを基準とし、モーション低減時は即時切替にする。

### Error

- 入力内容を消さず、分析面内にエラーを表示する。
- 見出しは `分析できませんでした`、操作は `もう一度分析する` とする。
- 通信失敗とJev評価失敗はユーザー向け文言を分けるが、内部情報やスタックトレースは表示しない。
- エラー表示後も `入力を編集` を利用できるようにする。

## Result Hierarchy

結果はカードを5枚並べるのではなく、1つの分析面の中に水平な評価レーンとして積む。

1. SP分類：SとPを2本並べ、数値を他項目より1段大きくする。
2. 近接遭遇分類：`CE2｜第二種接近遭遇`と適合度を一緒に読む構造にする。
3. TRUE UFO度：値と注意文を近接させる。
4. 証拠強度：Pとは別のレーンとして明確に分離する。
5. フェイク兆候：注意色は使うが、危険判定や断罪に見せない。

バーの左端は0、右端は各尺度の最大値とする。SとPは値を10倍して幅へ変換し、その他は0〜100の値をそのまま割合として使う。

## Visual System

既存のUFO Labトークンを基礎に、Jenny専用の役割を追加する。

| Role | Value | Usage |
| --- | --- | --- |
| Page background | `#f6f7f3` | 既存の明るいページ背景 |
| Input surface | `#ffffff` | 入力面 |
| Primary ink | `#1f2420` | 明るい面の本文と見出し |
| Muted ink | `#667069` | 明るい面の補助文 |
| Brand sage | `#405f51` | 主ボタン、フォーカス、確からしさ |
| Analysis background | `#101814` | 暗い分析面 |
| Analysis surface | `#17221c` | 評価行と状態面 |
| Analysis line | `#34463b` | 区切り線とバーのトラック |
| Analysis text | `#f2f7f3` | 暗い面の主要文字 |
| Activity ice | `#8fd6e4` | Jevの活動状態とストレンジネス |
| Evidence sage | `#93bda7` | Pと証拠強度 |
| Caution amber | `#d8ac63` | フェイク兆候の注意色 |

- 色だけで状態を伝えず、必ずラベルと数値を併記する。
- 赤、ネオン紫、虹色グラデーションは使用しない。
- グラデーション文字、過剰な発光、走査線、星空、レーダー風の装飾は使用しない。
- 本文とラベルは背景に対して4.5:1以上、大きな数値は3:1以上のコントラストを実装時に検証する。

## Typography

- 基本文字：既存の `Arial, "Hiragino Kaku Gothic ProN", "Yu Gothic", Meiryo, sans-serif`。
- 数値：基本文字のまま `font-variant-numeric: tabular-nums` を指定する。
- Jev状態、項目数、経過時間：`ui-monospace, SFMono-Regular, Menlo, Consolas, monospace`。
- 等幅書体は短い状態表示と数値だけに限定し、本文やボタンには使わない。
- 主要見出しは固定remスケールを使い、プロダクト画面で過度に大きな可変見出しを使わない。

## Motion And Timing

モーションは処理状態と情報階層の変化だけに使用する。

1. 分析開始：入力面をコンパクト表示へ移行し、分析面をアクティブ状態にする。`150〜200ms`。
2. 応答待ち：項目名と控えめな活動表示を見せる。架空の数値アニメーションは行わない。
3. Jev応答：20件の実値を同じ開始時刻で反映する。`180〜240ms`。
4. 収束：下位判定面を退かせ、5指標を前面へ出す。`300〜450ms`。
5. 最終バー：5本すべてを同じ開始時刻で0から実値へ伸ばす。逐次表示に見える長いスタッガーは使わない。

イージングは強いバウンドやスプリングを避け、`cubic-bezier(0.16, 1, 0.3, 1)`を基本とする。幅の変更はバー内部の`transform: scaleX()`で行い、レイアウトを継続的に再計算させない。

`prefers-reduced-motion: reduce`では、値と結果を即時表示するか `100ms`以下のクロスフェードだけを使用する。情報の表示をアニメーション完了に依存させない。

## UI Data Contract

UIは実装時に、次の情報を受け取る前提とする。具体的な型名とAPI形式はDATA.mdで確定する。

- `microSignals`：20件固定。`id`、グループ、短い日本語ラベル、実値、最大値、表示トーンを持つ。
- `summary`：S、P、CEコード、CE分類名、CE適合度、TRUE UFO度、証拠強度、フェイク兆候を持つ。
- `durationMs`：Jev評価に要した実測時間。
- `questionCount`：初期仕様では常に20。UIの実績表示は固定文言ではなくこの値を使う。

未到着の値を0として表示しない。0はJevが実際に0を返した場合だけ表示する。

## Interaction States

- **Empty input**：主ボタンを無効化し、入力が必要であることをラベルで示す。
- **Too short**：入力面の直下へ短い検証メッセージを表示し、分析を開始しない。
- **Submitting**：入力を保持し、主ボタンと二重送信を無効化する。
- **Success**：入力を折りたたみ、結果へフォーカスを移す。
- **Retry**：同じ入力を保持したまま再分析できる。
- **Edit after result**：入力を展開すると結果は残す。再分析を開始した時点で古い結果を待機状態へ戻す。

## Accessibility

- すべての操作要素にキーボードフォーカスを表示し、タップ対象を最低 `44px` にする。
- 結果の開閉ボタンには`aria-expanded`と`aria-controls`を設定し、EnterとSpaceで操作できるようにする。
- 分析状態は `aria-live="polite"` で `20項目を分析中`、`20項目の分析が完了`、エラーを通知する。
- 20件の途中値を個別に読み上げて利用者を圧倒しない。最終5表示ブロックは意味のあるラベルを持つ`dl`または同等の構造で読み上げる。
- バーにはラベル、現在値、最小値、最大値を関連付ける。色やバー長だけに依存しない。
- 分析開始後のフォーカス移動は、ユーザーが現在位置を失わないよう状態見出しへ行う。
- プレースホルダーを入力ラベルの代用にしない。
- 320px幅でも横スクロールを発生させず、長い日本語ラベルを省略しない。

## Footer

- 注意文をワークスペース直後の独立した領域に置き、その下にUFO Lab Tokyo共通フッターを表示する。
- 共通フッターにはホームへのリンク、著作権表示、Xのフィードバック導線を含める。

## Social Preview

- Open GraphとXカードでは、同じ1200×630pxのPNG画像を使用する。
- 共有画像はタイポグラフィを中心に構成し、淡いグレーの背景、深いグリーン、アイスブルー、セージのJennyカラーを継承する。
- 主表示は`Jenny`、副表示は`UFO REPORT ANALYZER`とし、`UFO報告文書をJevで分析`、`20の型付き判定 / 5つの指標`、`UFO LAB TOKYO`、`ufolab.tokyo/jenny`を明記する。
- 実際の分析結果と誤認される架空のスコア、確率、ゲージは表示しない。
- 日本語と英字が1200×630px内で欠けず、縮小表示でも名称と用途を識別できる文字サイズとコントラストを確保する。

## Verification Targets

- 待機、分析、完了、通信失敗、Jev失敗、再分析の各状態を確認する。
- 20件の型付き判定に、Jev応答前の架空数値が表示されないことを確認する。
- 5本の最終バーが表示値と一致し、同じ開始時刻で描画されることを確認する。
- 320px、390px、768px、1280pxで入力、状態、5指標、操作が欠落しないことを確認する。
- キーボード操作、フォーカス順、読み上げ通知、コントラスト、モーション低減を確認する。
